# EIT003 — Contract module leaks a non-kernel dependency
Contracts must be leaves: a module under `contract/` may import only the standard library, the kernel package (`pfa.kernel`), and its own Contract. Anything else (another feature, a third-party package such as FastAPI or pydantic, the application, the feature's own `internal/`) makes consuming the contract drag in transitive context — the exact failure mode the architecture exists to prevent. The rule checks *imports* rather than signatures because an import is the context an agent actually loads to consume the contract.
**Fix:** map the foreign type to a kernel primitive or a DTO owned by this Contract; keep framework models at the HTTP edge, `src/pfa/api/routes/<feature>.py`, which is the only place pydantic belongs (EIT006). A deliberately shared third-party package can be allowed with `contract_allowed_modules` in `[tool.eitri]`.
