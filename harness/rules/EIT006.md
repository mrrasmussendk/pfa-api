# EIT006 — Slice depends upward
A feature (a vertical slice) is messages in, `Result` out. Above it sit the application (`pfa/application.py`, which plugs features in) and the application's entry points (`pfa/api`, where the pydantic request and response models, the `APIRouter`, the status codes and the `Problem` responses live). A feature may import only what is below or beside it: the kernel and the contracts it declares. The moment a feature imports `fastapi`, `starlette`, `pfa.application` or anything from `pfa.api`, it has grown an edge of its own: the framework leaks into the working set of everyone who opens the feature, "internal" starts to mean "used by the entry point after all", and handlers are one shortcut away from raising HTTP errors instead of returning `Result`. The rule flags any module under `src/pfa/features/` outside `contract/` that imports either framework or anything from the application package that is not a feature contract or the kernel, including lazily inside a function. Inside `contract/` the import is already an EIT003 violation and EIT006 stays silent, so one line yields one remedy. Pydantic is not an HTTP framework and is not flagged; it is simply not needed in a feature, because validation of the wire shape is the edge's job.
The application package the diagnostic names is `app_package` in `[tool.eitri]` (default `pfa`), so the rule itself knows nothing about this project.
**Fix:** move the route, its models and its error mapping to `src/pfa/api/routes/<feature>.py`; if the feature needs to signal an infrastructure failure to the edge (a saturated model, a timeout), raise a plain exception declared in its `contract/` and let the route map it to a `Problem`. If the feature needs something the application has, it is a kernel primitive or it is a message on the bus. See `harness/guides/adding-a-route.md`.
