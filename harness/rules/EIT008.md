# EIT008 — Breaking contract change
A contract is everything other code may rely on. `eitri check --base origin/main` compares each feature's `contract/` with the same files at the merge base. Additions are free: a new message, a new public name, a field or trailing parameter with a default. Removing or changing a public member fails when anything outside the owning feature used it at the base: another feature, the composition root, or another feature's routes. The feature's own routes module is part of the feature and doesn't count. The Stop hook and CI run the check.

This is the expand-contract migration from [Changing a contract](../guides/changing-a-contract.md), as a check: the change that removes a member can only land once nothing uses it.
**Fix:** keep the old member and add the replacement beside it, migrate every consumer the diagnostic names, then remove the old member in a later change.
