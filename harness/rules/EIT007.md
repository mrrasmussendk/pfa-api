# EIT007 — Feature dependency cycle
`feature.json` says which features a feature depends on, and the walls assume those dependencies point one way: a feature is understood, changed and budgeted through the contracts *below* it. A cycle (`a → b → a`, or longer) breaks that. Neither feature can be read without the other, a change to either reaches both, and the slice map's fan-in and reach stop meaning anything. EIT007 fails the check on any cycle among the declared dependencies, naming the features around it.
**Fix:** decide which way the dependency should point and remove the other declaration (and its imports). If both features need the same thing, move it into one of them, or into a new feature both depend on.
