Serves `intfloat/multilingual-e5-large`: text in, unit-normalised 1024-dim vector out. The model **embeds**, it does not answer — a question becomes a query vector to rank passages against.

- **CQRS.** The contract is three queries (`EmbedQuery`, `EmbedPassages`, `RankCandidates`) in `contract/queries.py` and their result types in `contract/results.py`. One handler per query in `internal/handlers.py`; `module.py` registers them on the bus. Routes dispatch a query, never call a handler. To add a use case: a query dataclass, a result type, a handler, one `bus.register` line, a route.
- **Chunking is another slice.** The model's window is 512 tokens and it truncates silently. `PFA_EMBED_MAX_TOKENS` (default 500) is the ceiling including the prefix; the handlers dispatch `SplitText` / `CountTokens` from `slices.chunking.contract` on the bus (declared in `slice.json`) to fit text to that budget. Passages come back one result per chunk with `source_index` / `chunk_index` / `chunk_count`; a candidate's similarity score is its best chunk's; a long question is chunked and mean-pooled into one vector.
- Working set: this folder + `src/slices/chunking/contract/` + `src/shared_kernel/`. Never `src/slices/chunking/internal/`. The model wrapper is `internal/e5_engine.py`; it loads lazily on the first request (2 GB, seconds), never at import or in `create_app()`.
- e5 needs a prefix per side: `query: ` for questions, `passage: ` for documents. Only the engine knows the prefixes; callers choose the side by choosing the query.
- Config: `PFA_EMBED_MODEL`, `PFA_EMBED_DEVICE` (`cuda` / `cpu`; default picks CUDA when available), `PFA_EMBED_MAX_TOKENS`, `PFA_EMBED_CONCURRENCY` (encodes at once, default 1), `PFA_EMBED_QUEUE_TIMEOUT` (seconds before `EngineBusy`). Weights: `python tools/download_model.py`.
- **Concurrency.** Routes are sync `def` (threadpool); the engine serialises `encode` behind a `BoundedSemaphore` so a burst queues instead of running N inferences at once. `EngineBusy` (gate timeout) is infrastructure, not a domain outcome: handlers let it propagate and `routes.py` turns it into a `503` `model-busy` problem with `Retry-After`. The one-time load is a separate lock and happens *outside* the gate, so a cold start never holds the inference slot.
- **Readiness.** `module.py` exposes `ready()` (loaded flag, loads nothing) and `warmup()` (load now); the composition root wires them into `GET /ready` and the `PFA_WARMUP` startup thread. Never make `/health` depend on the model.
- Tests never load the model: `tests/api/test_embeddings.py` registers the real handlers of both slices over a `FakeTokenizer` (whitespace words) and a `FakeEngine` (letter-bag vectors). The real-model tests run only with `PFA_RUN_MODEL_TESTS=1`.
