# Changelog

## Unreleased
- RFC 9457 Problem Details: every error response is `application/problem+json` with `type` / `title` / `status` / `detail` / `instance`. New `src/http_common/` package (`Problem`, `install_problem_details`) wired in `create_app()`; domain rejections are `urn:pfa-api:problem:domain-rejection`, request validation failures `urn:pfa-api:problem:validation-error` (with an `errors` extension), 404/405/500 are `about:blank`. OpenAPI documents the error responses as `ProblemDetails`.
- EIT005 HTTP error bypasses Problem Details: `HTTPException` from `fastapi`/`starlette` is banned inside `src/slices/`; routes raise `http_common.Problem` (the remedy named in the diagnostic is `[tool.eitri] problem_helper`). Brokkr canary and rule doc added.
- `docs/guides/returning-errors.md`: what a route raises, what the client receives, how to add a problem type.
- Endpoint validation (`http_common.validation`): request models are `StrictRequest` (unknown fields → 422), text fields are `text(max)` (length bounds, control characters rejected with position), lists of texts are capped per item and per request (`check_total_chars`, 2 000 000 characters). Semantic checks stay in the handlers.
- Model async handling: the engine serialises inference behind a bounded gate (`PFA_EMBED_CONCURRENCY`, default 1; `PFA_EMBED_QUEUE_TIMEOUT` → `503` `urn:pfa-api:problem:model-busy` with `Retry-After`), loads outside the gate, and returns vectors via `tolist()`. `GET /ready` (503 `not-ready` until tokenizer + model are loaded) beside the async liveness `GET /health`; `PFA_WARMUP=1` preloads on a background thread at startup (on in the image). Per-text size cap on passages/candidates. `pfa-api` gains `PFA_WORKERS`, `PFA_LOG_LEVEL`, `PFA_ACCESS_LOG`, `PFA_FORWARDED_ALLOW_IPS`, graceful-shutdown timeout. Each slice's `module.py` exposes `ready()` / `warmup()`.
- Linters: Ruff (lint + format, `[tool.ruff]`, line length 140, py310 target, isort with the repo's first-party packages) and mypy (`[tool.mypy]`; the service packages are `disallow_untyped_defs`). Both run first in CI's `enforce` job; the whole tree is clean. Real findings fixed along the way: `zip(..., strict=True)` in the embeddings handlers, lambdas capturing loop variables in `heimdall map`, an unchecked `subprocess.run`, a shadowed loop variable in Eitri's walls.
- Tests: `filterwarnings = ["error"]` — any warning fails the suite. Dev dependency `httpx` replaced by `httpx2`, which Starlette's `TestClient` now expects.
- `heimdall review`: Jev (TypeSafe AI System One API) judges a diff with typed questions — gates (`safe_to_merge`, `needs_human_review`, `has_security_concern`), rubrics (`correctness`, `clean_code`, `blast_radius`, `docs_in_sync`), wall and Problem-Details fit — over bounded state built from the diff, the slice map and the PR text; policy in code maps to approve / comment / request_changes / escalate (exit 0/1/2; 3 = could not review). JSON + Markdown reports, a `review` telemetry line, `--dry-run`, retries on 429/529. Stdlib only.
- `.github/workflows/pr-review.yml`: runs `heimdall review` on every PR, posts a sticky comment, fails on request_changes, labels `needs-human-review` on escalate, skips cleanly when the key is absent (forks). Guide: `docs/guides/pr-review.md`.
- Heimdall: `[tool.heimdall] shared = [...]` names packages every slice may read besides the kernel (`http_common`); `heimdall map` records them, the read sensor classifies them `shared:<pkg>`, and `heimdall drift` counts them in-bounds.

## 0.1.0
- CI/CD: `enforce` (walls, canaries, tests, smoke test, stale-map check on Linux + Windows) → `wheel` (no tooling inside) → `image` (multi-stage Dockerfile, booted and verified, pushed to GHCR on `main` and `v*` tags). `docker-compose.yml` for local runs with a persistent model volume.
- CQRS: slice contracts are messages (`Query`/`Command` dataclasses) + result types; one handler per message; a kernel `Bus` replaces the `Registry`. Routes and slices dispatch, never call services.
- Chunking: text over the model's window (`PFA_EMBED_MAX_TOKENS`, default 500) is split on sentence boundaries using the model tokenizer; passages return one vector per chunk, similarity scores a candidate by its best chunk, long questions are mean-pooled.
- `chunking` slice (`CountTokens`, `SplitText`, `POST /chunking/split`): the first cross-slice dependency — `embeddings` declares it and consumes it through the bus.
- `POST /embeddings/passages` and `POST /embeddings/similarity` added beside `POST /embeddings/query`.
- PFA API: a FastAPI service built as vertical slices (`src/pfa_api` composition root, `src/shared_kernel`, `src/slices/embeddings` serving `intfloat/multilingual-e5-large` on `POST /embeddings/query`). `python -m pfa_api` runs it. The Kvad/Rune demonstration slices from the original project were removed.
- Architecture tooling ported from the .NET project `brokkr-eitri` (Roslyn analyzers + NativeAOT `heimdall` CLI) to pure-stdlib Python 3.10+, packaged separately under `tools/` as `pfa-devtools` so it is never deployed.
- EIT001 public-surface-outside-Contract, EIT002 escape-hatch ban, EIT003 contract purity — re-expressed as import-graph walls, since Python has no compiler-enforced visibility.
- EIT004 undeclared slice dependency: the `slice.json` manifest replaces the csproj graph.
- EIT100/EIT101 context-budget fitness function; dependency surfaces reconstructed from the AST as body-less stubs (`eitri surface`).
- Built-in token estimator, same chunking rules as the original, configurable via `[tool.eitri] token_budget`.
- Heimdall `map` / `hook` / `drift` / `estimate` with the same file formats (`.heimdall/map.json`, `telemetry.jsonl`, `session-<id>.json`, `AGENTS.md` markers). `map.json` paths are always forward-slash.
- Brokkr canary suite (`tools/brokkr_canary.py`), harness smoke test (`tools/smoke_test.py`), rule scaffold (`tools/new_rule.py`), synthetic fixture tree (`tools/fixtures.py`).
