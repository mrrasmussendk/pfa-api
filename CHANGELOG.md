# Changelog

## Unreleased
- Function shape: `tools/heimdall/shape.py` states the two clean-code facts an AST can — a function's length and parameter count (limits 40 lines, 5 parameters; `self`/`cls` not counted). The `function_shape` hook sensor tells the agent right after an `Edit`/`Write`/`MultiEdit` which function it touched is over a limit (exit 2, the function named with its line; only touched functions, tests left out). `heimdall review` hands the judge the same list as `facts.function_shape` / `facts.function_limits` and asks three new questions about it — `single_purpose`, `lean_signatures` (yes/no) and `readability` (0–3) — while `clean_code` is narrowed to duplication, dead code, comments and style. Policy: a `No` on single purpose or lean signatures **with** a function named by the AST is `request_changes` naming the function; either alone is a `comment` note; `approve` now also needs `single_purpose ≥ 0.5`, `lean_signatures ≥ 0.5`. Readability and clean code have **targets** (2.5 and 2.8 on 0–3, `T["readability_target"]` / `T["clean_target"]`): below them, when any Python outside tests changed (`facts.code_changed`), the check fails so the agent is sent back, and the advice quotes the judge's `readability_limit` / `clean_code_limit` choice (names, nesting, length, mixed levels, magic values, cleverness; duplication, dead code, comments, style, error handling) with the fix for it. The comment lists the functions over the limits under "What Heimdall told the judge". `review.run` takes a `Streams` tuple; the review's own modules were split to pass their own limits.
- Logging follows RFC 5424, RFC 3339 and W3C Trace Context (`docs/decisions/0001-logging.md`). `pfa/api/logs.py` configures one stream on stdout (`PFA_LOG_FORMAT=syslog|json`, `PFA_LOG_FACILITY`, `PFA_LOG_ENTERPRISE_NUMBER`), with uvicorn's loggers writing through it; a pure-ASGI `TraceContext` middleware starts a span from the client's `traceparent` (or a new trace), echoes `traceparent`, passes `tracestate` through and logs one `request` line (method, path, status, ms, client; probes at debug, `5xx` at err). The engine logs `load`, `encode` (side, texts, chars, wait_ms, encode_ms, device) and `busy` (warning); the 500 handler logs the traceback with method and path. Every problem document carries `trace_id` (documented in OpenAPI). Never the user's text. **Operators:** uvicorn's access log is now off by default (`PFA_ACCESS_LOG=1` restores it); the image logs JSON.
- The tree now reads top-down: `src/pfa/` is **the application**. `application.py` (the former composition root, moved out of the API) registers every feature on one bus with no HTTP; `features/` holds the former `slices/` (manifests renamed `feature.json`); `kernel/` is the former `shared_kernel`; `api/` is the former `pfa_api`, now one entry point among the application's parts (`python -m pfa.api`, `pfa.api.app:create_app`). Imports are `pfa.features.<x>.contract`, `pfa.kernel`, `pfa.api.problems`. The package inits of `pfa` and `pfa.api` import nothing (features import the kernel, routes import `problems`; an eager app import would loop).
- Eitri is prefix-aware (`slice_prefix = "pfa.features."`, `kernel = "pfa.kernel"`), polices the whole application package outside the features and kernel (`app_package = "pfa"`), and names the one module that may import a feature's `module.py` (`composition_root = "pfa.application"`; from anywhere else it is EIT001). EIT006 is now "slice depends upward": no `fastapi`/`starlette` *and nothing from the application or its entry points* inside a feature. `eitri check` reports `no pfa/features/ under …` when the layout is missing.
- Heimdall takes the layout from `[tool.heimdall]` as paths (`features`, `kernel`, `app`, `routes`), records `kernel_dir` / `app_dir` / `routes_dir` in the map, and the root `AGENTS.md` block is now a "Feature map".
- Slices no longer own an HTTP edge. Routes moved from `src/slices/<x>/internal/routes.py` to `src/pfa_api/routes/<x>.py` (one module per slice, consuming the slice through its contract and the bus like any other caller; `ROUTERS` in `pfa_api/routes/__init__.py` is what `create_app()` mounts); each slice's `module.py` (`register(bus)`, `ready()`, `warmup()`) moved from `internal/` to the slice root and no longer exports a router; `http_common` folded into the app package as `pfa_api/problems.py` and `pfa_api/validation.py`; `EngineBusy` moved into the embeddings contract (`contract/errors.py`) so the route can map it without touching `internal/`. Slices import neither FastAPI nor pydantic.
- Eitri: `[tool.eitri] app_package` (default `pfa_api`) names the composition root + HTTP edge, which is now policed too — EIT001 against any `slices.<x>.internal` import (a slice's `module` is allowed only there, and is EIT001 from another slice), EIT005 against `HTTPException` (the module that defines `problem_helper` is exempt: it is the conversion point). New **EIT006** — HTTP framework inside a slice: no `fastapi`/`starlette` import anywhere under `src/slices/` outside `contract/`. `problem_helper` default is `pfa_api.problems.Problem`. Brokkr canaries for EIT006 and for the app-package EIT001/EIT005; fixture tree gains a `pfa_api` package.
- Heimdall: `[tool.heimdall] app` (default `pfa_api`) replaces `shared = ["http_common"]`; `heimdall map` inventories routes from `<app>/routes/<slice>.py` and records `app` in the map; `<app>/routes/<slice>.py` classifies as `slice:<slice>` for the sensors, the review state (`routes_changed`) and `heimdall drift`; any other read in the app package is kind `app` and in-bounds.
- Docs: `AGENTS.md`, `docs/architecture.md` (new "The HTTP edge" section), `docs/tooling.md`, `harness/guides/adding-a-route.md`, `harness/guides/returning-errors.md`, `harness/rules/EIT001|003|005|006.md`, `docs/diagrams/dependencies.mmd` describe the new layout.
- RFC 9457 Problem Details: every error response is `application/problem+json` with `type` / `title` / `status` / `detail` / `instance`. New `src/http_common/` package (`Problem`, `install_problem_details`) wired in `create_app()`; domain rejections are `urn:pfa-api:problem:domain-rejection`, request validation failures `urn:pfa-api:problem:validation-error` (with an `errors` extension), 404/405/500 are `about:blank`. OpenAPI documents the error responses as `ProblemDetails`.
- EIT005 HTTP error bypasses Problem Details: `HTTPException` from `fastapi`/`starlette` is banned inside `src/slices/`; routes raise `http_common.Problem` (the remedy named in the diagnostic is `[tool.eitri] problem_helper`). Brokkr canary and rule doc added.
- `harness/guides/returning-errors.md`: what a route raises, what the client receives, how to add a problem type.
- Endpoint validation (`http_common.validation`): request models are `StrictRequest` (unknown fields → 422), text fields are `text(max)` (length bounds, control characters rejected with position), lists of texts are capped per item and per request (`check_total_chars`, 2 000 000 characters). Semantic checks stay in the handlers.
- Model async handling: the engine serialises inference behind a bounded gate (`PFA_EMBED_CONCURRENCY`, default 1; `PFA_EMBED_QUEUE_TIMEOUT` → `503` `urn:pfa-api:problem:model-busy` with `Retry-After`), loads outside the gate, and returns vectors via `tolist()`. `GET /ready` (503 `not-ready` until tokenizer + model are loaded) beside the async liveness `GET /health`; `PFA_WARMUP=1` preloads on a background thread at startup (on in the image). Per-text size cap on passages/candidates. `pfa-api` gains `PFA_WORKERS`, `PFA_LOG_LEVEL`, `PFA_ACCESS_LOG`, `PFA_FORWARDED_ALLOW_IPS`, graceful-shutdown timeout. Each slice's `module.py` exposes `ready()` / `warmup()`.
- Linters: Ruff (lint + format, `[tool.ruff]`, line length 140, py310 target, isort with the repo's first-party packages) and mypy (`[tool.mypy]`; the service packages are `disallow_untyped_defs`). Both run first in CI's `enforce` job; the whole tree is clean. Real findings fixed along the way: `zip(..., strict=True)` in the embeddings handlers, lambdas capturing loop variables in `heimdall map`, an unchecked `subprocess.run`, a shadowed loop variable in Eitri's walls.
- Tests: `filterwarnings = ["error"]` — any warning fails the suite. Dev dependency `httpx` replaced by `httpx2`, which Starlette's `TestClient` now expects.
- `heimdall review`: Jev (TypeSafe AI System One API) judges a diff with typed questions — gates (`safe_to_merge`, `needs_human_review`, `has_security_concern`), rubrics (`correctness`, `clean_code`, `blast_radius`, `docs_in_sync`), wall and Problem-Details fit — over bounded state built from the diff, the slice map and the PR text; policy in code maps to approve / comment / request_changes / escalate (exit 0/1/2; 3 = could not review). JSON + Markdown reports, a `review` telemetry line, `--dry-run`, retries on 429/529. Stdlib only.
- `.github/workflows/pr-review.yml`: runs `heimdall review` on every PR, posts a sticky comment, fails on request_changes, labels `needs-human-review` on escalate, skips cleanly when the key is absent (forks). Guide: `harness/guides/pr-review.md`.
- Heimdall: `[tool.heimdall] shared = [...]` names packages every slice may read besides the kernel (`http_common`); `heimdall map` records them, the read sensor classifies them `shared:<pkg>`, and `heimdall drift` counts them in-bounds.

## 0.1.0
- CI/CD: `enforce` (walls, canaries, tests, smoke test, stale-map check on Linux + Windows) → `wheel` (no tooling inside) → `image` (multi-stage Dockerfile, booted and verified, pushed to GHCR on `main` and `v*` tags). `docker-compose.yml` for local runs with a persistent model volume.
- CQRS: slice contracts are messages (`Query`/`Command` dataclasses) + result types; one handler per message; a kernel `Bus` replaces the `Registry`. Routes and slices dispatch, never call services.
- Chunking: text over the model's window (`PFA_EMBED_MAX_TOKENS`, default 500) is split on sentence boundaries using the model tokenizer; passages return one vector per chunk, similarity scores a candidate by its best chunk, long questions are mean-pooled.
- `chunking` slice (`CountTokens`, `SplitText`, `POST /chunking/split`): the first cross-slice dependency — `embeddings` declares it and consumes it through the bus.
- `POST /embeddings/passages` and `POST /embeddings/similarity` added beside `POST /embeddings/query`.
- PFA API: a FastAPI service built as vertical slices (`src/pfa_api` composition root, `src/shared_kernel`, `src/slices/embeddings` serving `intfloat/multilingual-e5-large` on `POST /embeddings/query`). `python -m pfa_api` runs it. The Kvad/Rune demonstration slices from the original project were removed.
- Architecture tooling ported from the .NET project `brokkr-eitri` (Roslyn analyzers + NativeAOT `heimdall` CLI) to pure-stdlib Python 3.10+, packaged separately under `tools/` as `pfa-devtools` so it is never deployed.
- EIT001 public-surface-outside-Contract, EIT002 escape-hatch ban, EIT003 contract purity — re-expressed as import-graph walls, since Python has no compiler-enforced visibility.
- EIT004 undeclared slice dependency: the `slice.json` manifest replaces the csproj graph.
- EIT100/EIT101 context-budget fitness function; dependency surfaces reconstructed from the AST as body-less stubs (`eitri surface`).
- Built-in token estimator, same chunking rules as the original, configurable via `[tool.eitri] token_budget`.
- Heimdall `map` / `hook` / `drift` / `estimate` with the same file formats (`.heimdall/map.json`, `telemetry.jsonl`, `session-<id>.json`, `AGENTS.md` markers). `map.json` paths are always forward-slash.
- Brokkr canary suite (`tools/brokkr_canary.py`), harness smoke test (`tools/smoke_test.py`), rule scaffold (`tools/new_rule.py`), synthetic fixture tree (`tools/fixtures.py`).
